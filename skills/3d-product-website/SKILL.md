# 3D 产品网站（一万美金级别）

这个 skill 来自 BT-4 网站的实战：https://bt4-robot.pages.dev 。用户不需要会写代码，你负责写代码，用户负责给方向和参考。
说话用用户的语言，像带新手一样，一次只推进一步，每一步做完给用户看结果（截图或本机预览网址）。

## 先做对的五件事

一个 100 美元的网站和一个 10000 美元的网站，差在这五件事。整个流程都围绕它们，最后逐条验收（见 [references/checklist.md](references/checklist.md)）：

1. **目的**：访客看完要去做什么（买、留邮箱、预约）。一眼找得到按钮。
2. **设计**：看不出是模板或 AI 做的。避开紫色渐层、千篇一律的圆角卡片、emoji 堆砌。
3. **动态**：滚动有动画、3D 可以拖着转，不是一张图一段字一个按钮。
4. **手机**：手机、平板上一样好看，3D 不挡字。
5. **能用**：表单真的收得到，网站真的上线、有网址。

## 流程

### 1. 问清楚目的，再写计划

开工前先问用户（一次问完，没讲的用合理默认值）：
- 卖什么？目标访客是谁？希望访客最后做什么？
- 产品有没有图片？没有的话，愿不愿意先用 GPT Image 画设计图？
- 有没有喜欢的网站或作品当参考？

用户的需求如果还是零散的大白话，先把它整理成一份完整的提示词给用户确认（页面段落、可互动部位、表单、手机版排法），再照这份提示词写计划。
然后写一份计划给用户看，**先不要写代码**。计划包括：页面段落、3D 产品要有哪些可互动的部位、每个部位对应什么卖点、表单、上线方式。
同时在项目文件夹建 `AGENTS.md`，记录做到哪、做了什么决定、还有什么没做；之后每轮改完都更新，换对话也能接着做。

### 2. 第一版：功能先对

用 three.js（从 jsDelivr 载入固定版本，例如 `three@0.170.0`）做出第一版：
- 产品可拖曳旋转、放手慢慢回正
- 外观／X 光（外壳变半透明或边光）／拆解（零件沿各自方向飞出）三种状态
- 产品上的可点击部位 → 切换对应的商品介绍和购买按钮
- 本机预览：`python3 -m http.server` 之类的静态服务器

第一版通常「能用但很丑」。这是正常的，直接告诉用户，下一步靠参考变好看。

### 3. 用参考提升质感

用户说「做好看一点」时，不要自己猜，请用户给参考，或主动建议去哪里找：X 搜「three.js」「3D website」、Awwwards、Dribbble、大品牌官网（车厂、手表、消费电子）。
参考优先请用户给截图：有些网站打不开，或打开了看不到动画。给链接时如果打不开，直接请用户改给截图。
拿到参考后，先把它的设计语言拆成一张表给用户确认，再动手。一定要问清楚学哪一点：质感、配色、版型、节奏、文案语气，还是造型。只说「我喜欢这个质感」，容易连造型一起学歪。
做法和模板见 [references/reference-method.md](references/reference-method.md)。

### 4. 让产品更真实：先出图，再做 3D

用代码拼几何体，再怎么调都像玩具。要写实感时：
1. **写设计规格**：形状、材质、颜色、每个可互动部位的位置。
2. **写生图提示词**给用户拿去 GPT Image（ChatGPT 免费账号可用）：
   - 四分之三正面主视觉
   - 拆开的爆炸图
   - 正面／侧面／背面三视图
   - 统一用浅色摄影棚背景，不要文字和 logo
3. **图生 3D**：主视觉裁成正方形、背景弄干净，用 Hugging Face 上的 TRELLIS.2（微软开源，MIT）生成 GLB。用户可以在网页上传，也可以用 `gradio_client` 调用 Space。免费额度：不登录每天 2 分钟，免费账号 5 分钟，生成一次约 2 分钟。
   - **不要**把 Hugging Face token 写进任何文件或回复。需要登录时，请用户自己在终端跑 `hf auth login`。
4. **Blender 后处理**（用户装了 Blender MCP 就通过 MCP，没有就写 `bpy` 脚本，用 `blender --background --python` 跑）：
   - 减面（例如降到十几万面），贴图缩到 2048、转 JPEG
   - 按部位把一整块外壳切成可拆零件，每块记录拆解方向、顺序（存在 glTF extras），供网页读取
   - 补内部零件（骨架、齿轮、电路板……），让拆开或 X 光时里面有东西
   - Draco 压缩导出，目标 3 MB 以内；网页用 `GLTFLoader` 加 `DRACOLoader`

### 5. 统一整站设计

产品好看了，网站常常还像后台。请用户挑一个大品牌官网（例如车厂）当整站参考，总结它的设计语言后重做版面。常见可学的点：
- 全屏暗色摄影棚，产品占满画面，几乎没有面板
- 往下滚一格换一个镜头：每段一个镜头关键帧，滚动时在关键帧之间平滑插值
- 宽体大字配细线编号；暗色段和浅灰规格段交替
- 只用一个强调色
- 字体用 Google Fonts（例如宽体 Archivo，中文 Noto Sans）

**只学感觉**：不使用对方的 logo、字体文件、图片和文案。页尾写明提到的品牌名称属于各自所有者，与本站没有合作关系。
用户卖的产品如果挂在别人的平台或品牌下（例如某个 AI 平台的 Bot），主动提醒：3D 模型和主视觉不放那些品牌的 logo，只用文字名称。

接着：
- 文案照精品品牌的口气重写：短句、名词收尾、不用感叹号。要中英版时，英文另外写，不要直译。
- 可选：加一个「试玩页」，像汽车配置器那样，让访客自己换灯光、光色、透明度、拆解程度。

### 6. 手机版和速度

- 用 375×812 等尺寸逐段检查：3D 不挡标题和按钮，按钮字不挤成直排，画面不超出屏幕。修好后截图给用户。
- 手机版常见做法：产品放上半部，文字放下半部。
- 手机／桌机判断如果只在载入时做，测试时要先设好视窗大小再载入。
- 模型和贴图压缩，首屏不要等太久。

### 7. 表单

「新品通知我」邮箱表单，用 Cloudflare Pages Functions 加 D1。可直接参考 [assets/notify.js](assets/notify.js) 和 [assets/schema.sql](assets/schema.sql)：
- 邮箱转小写、验格式、`INSERT OR IGNORE`，重复的只存一笔，回应不透露是否登记过
- 隐藏的防机器人栏位：有值就假装成功、不写入
- 前端三种状态：送出中、成功、失败

建线上数据库（`wrangler d1 create`）、跑 schema、部署，都会改动用户的 Cloudflare 账号，**先问用户再做**。

### 8. 上线

- 用 Cloudflare Pages（免费，送 `*.pages.dev` 网址）。用户先注册免费账号，`npx wrangler pages deploy` 时会开浏览器让用户登录授权。
- **只上传网站真正用到的文件**：另建一个部署资料夹，放 html、js、css、模型、functions。不要把备份、原始素材、大模型一起传上去。
- 部署后打开线上版：检查主控台没有错误，表单实际送一笔、到数据库查得到。
- 自定义域名要另外买，先告诉用户不在免费范围内。

### 9. 验收

拿 [references/checklist.md](references/checklist.md) 跟用户逐条对一遍五件事、手机版、上线前检查。

## 选配：实时数据

如果产品跟某种实时数据有关（例如交易工具），可以让 3D 跟着数据动（例如齿轮转速跟着成交速度）。
- 币安公开行情只读、不用 key：`data-api.binance.vision`、`data-stream.binance.vision`
- 部分地区连不上，要做好降级：连不上就隐藏行情，页面照常运作
- 页面写明「只显示公开数据，不构成投资建议」
